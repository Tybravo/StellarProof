The event polling hook takes a stable Soroban RPC server, contract ID, submitted transaction hash, and the ledger immediately before submission. Supply the uploaded mediaCid, manifestCid, and requester public key. Polling returns the matching decoded event, loading state, or an error. It stops after two minutes by default. Keep the server instance stable across renders.

The expected contract topic is VerificationRequestEvent. Its ScMap payload contains media_cid, manifest_cid, and requester, with the requester encoded as a Stellar address. Camel-case CID field names are also accepted. The caller must use the ledger from the submission to stay within RPC event retention.

Render VerificationProgress with a streamUrl for the authenticated job endpoint. useSpvUpdates accepts both default SSE messages and named status messages with a JSON status field. It supports pending, processing, tee_verifying, minting, completed, and failed. Native EventSource reconnects on transient interruption and the hook closes on terminal status or unmount. Authentication must be cookie based or provided by a same-origin proxy because native EventSource cannot attach a bearer header.

Integration prerequisites remain in the upstream application. SUMMARY_TYPESCRIPT.md is absent. The current oracle contract stores a content hash and emits no VerificationRequestEvent with CIDs and requester. The existing submission service calls provenance mint and returns no backend job ID. The statusStream service logs broadcasts without delivering them. Consequently, these frontend components are ready for the specified interfaces and are tested with injected RPC/SSE fixtures, but live end-to-end verification requires the contract event, submission-to-job mapping, and backend stream delivery. Mount the dashboard once that flow supplies the job stream URL. The current PR keeps the frontend scope requested by the contributor.
